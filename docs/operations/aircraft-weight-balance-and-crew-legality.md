# سجل الطائرات والوزن والتوازن وشرعية الطاقم

تاريخ التحقق: 3 نوفمبر 2026. هذه الدفعة تضيف نواة حساب قابلة للتدقيق
وحقول بيانات خاضعة لسيطرة المشغّل. لا تجعل وحدة الوزن والتوازن مقبولة
تشغيلياً ولا تستبدل دليل عمليات الناقل أو AFM/AHM المعتمد.

## حدود الإنتاج

- لا تقبل نواة `operational-weight-balance.service.ts` إلا تسجيلاً وملف توازن
  بحالة `accepted`، ومعرّف دليل، وموافقاً عليه، ونافذاً عند لحظة الحساب.
- تُخزّن قيمة DOW وDOI لكل تسجيل وإصدار مستقل. ثوابت تحويل الفهرس إلى `%MAC`
  ونقاط غلاف ZFW/TOW/LAW وحدود LMC تأتي من ملف المشغّل، ولا توجد قيم افتراضية.
- تنتج النواة ZFW وTOW وLAW ومواضع `%MAC` والـunderload وفحص LMC. كل مرحلة
  تُفحص مقابل غلافها المستقل بالاستيفاء الخطي بين نقاط المشغّل.
- الوثيقة الموقعة تظل `LOAD_SHEET_DRAFT` وتحتوي
  `dispatchAcceptanceRequired: true`. توقيع HMAC يحمي سلامة المسودة داخل AIS،
  ولا يمثّل توقيع قائد الطائرة أو مشرف التحميل.
- جداول `aircraft_registrations` و`aircraft_balance_profiles` و
  `load_sheet_documents` مضافة إلى مخطط Drizzle. ملف SQL يُولّد مركزياً مع
  بقية تغييرات هذه الدفعة.

## شرعية الطاقم

ظل مسار التعيين fail-closed. لا يُقبل التعيين إلا إذا وجد ملف سياسة واحد
موقّع من مصدر المشغّل، ساري على كامل المناوبة ومطابق للناقل والطراز والمستأجر.
أضيفت حدود تراكم زمن الطيران لـ28 و365 يوماً كقيم اختيارية يوردها المشغّل.
عند وجودها، يوسّع الاستعلام التاريخي نافذته ويطبقها كقيود صلبة. عدم وجود
القيمة لا يولّد حداً تخمينياً ولا يبرر ادعاء مطابقة GACAR Part 117.

## المتجهات المرجعية المحلية

يغطي الاختبار الحتمي مثالاً مجرداً بثوابت مشغّل اختبارية. ينتج:

| القيمة               |                   النتيجة |
| -------------------- | ------------------------: |
| DOW / DOI            |          40,000 kg / 10.0 |
| Traffic load / index |            8,000 kg / 2.0 |
| ZFW / index / %MAC   | 48,000 kg / 12.0 / 25.00% |
| TOW                  |                 58,000 kg |
| LAW                  |                 53,000 kg |
| Underload            |                 12,000 kg |

هذه أرقام اختبار برمجي فقط. يجب أن تستبدل بحالات مرجعية صادرة من هندسة وزن
وتوازن الناقل لكل طراز وتسجيل قبل رفع بوابة `demo`.

## المصادر الأولية التي أُعيد التحقق منها

- [GACAR Part 117 Version 3.0](https://www.gaca.gov.sa/-/media/Files/PDF/LawsAndRegulation/Aviation-Safety-and-Environmental-Sustainability/GACAR-Safety-Regulations/Part-117---Flight-and-Duty-Limitations-and-Rest-Requirements_-Flight-Crew-Members.pdf?as=0&hash=D9FDF15344B8B0D462551F2ADCF11331)
  يتضمن §§117.7 و117.11–117.25 والجداول A/B/C. يحمل الملف نفسه عبارة أن النسخة
  المنزلة غير مضبوطة وأن موقع GACA هو المرجع للإصدار الحالي. لذلك لم تُنسخ
  الجداول إلى الكود.
- [EASA Easy Access Rules for Air Operations, Revision 24, March 2026 — CAT.POL.MAB.105](https://www.easa.europa.eu/en/document-library/easy-access-rules/online-publications/easy-access-rules-air-operations?erules-id=ERULES-1963177438-12516)
  يطلب بيانات ووثيقة وزن وتوازن قبل الرحلة، تحقق سلامة خرج النظام المحوسب،
  توقيع مشرف التحميل وقبول القائد، وإجراء LMC مع إصدار وثيقة جديدة عند تجاوز
  الحد الذي يحدده المشغّل.
- [EASA Air Operations FAQ](https://www.easa.europa.eu/en/the-agency/faqs/air-operations)
  يؤكد أن التحميل يكون تحت إشراف شخص مؤهل وأن طريقة النظام تُحدد في دليل
  عمليات المشغّل.

## المتبقي للقبول

1. توليد الترحيل المركزي ومراجعته وإعادة تشغيله على MySQL 8 من قاعدة نظيفة
   وأخرى مأهولة.
2. تحميل بيانات التسجيل والطراز من مصدر المشغّل الموقع وربط دليل AFM/AHM
   وإلغاء الإصدار السابق عند التغيير.
3. مطابقة حالات مرجعية مستقلة لكل تسجيل، بما فيها حدود الغلاف وحالات LMC.
4. تسجيل توقيع مشرف التحميل وقبول القائد بهوية قوية وسجل وقت ومكان، وإبقاء
   نسخة أرضية من الوثيقة النهائية.
5. إدخال جداول GACAR Part 117 وبيانات التمديد والراحة/WOCL بعد اعتمادها من
   قسم عمليات الطيران، ثم اختبارها مقابل حالات المنظّم.
6. قبول تشغيلي مؤرخ قبل إزالة `weightBalance: demo` أو `loadPlanning: demo`.
