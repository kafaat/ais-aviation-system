الأساس: `b8e459096bfa1f9c12eb490b4fead61e65764732`، الإصدار `v1.22.9` بعد #142. هذه المتابعة تغلق قراءة التقارير المالية العامة وصيغها وتكامل مستودع البيانات. لا تضيف ترحيلة ولا تعدّل قيود المال التاريخية. المالك المذكور أدناه هو المكون البرمجي؛ تعيين المسؤول البشري والاعتماد المحاسبي يبقيان لدى الجهة المشغلة.

كتالوج الخدمات المولد يرصد الوحدات والاستيرادات؛ أسماء الجداول داخل SQL الخام لا تعني إنشاء مالك كتابة جديد. صفوف القنوات تستخدم EXISTS وتجميع القيود يسبق بيانات الوصف، حتى لا تضاعف الروابط أو عدد الدافعين المال. تتجمع أعداد القيود المتكررة مرة لكل مرجع مزود/حجز محفظة قبل المطابقة، لتجنب إعادة مسح الدفتر لكل صف تحصيل.

## العقد المالي v2 وترقية المستهلكين

- `schemaVersion=2` و`basis=posted_booking_ledger` و`currency=SAR` و`periodBasis=ledger_transaction_date_utc`. حقول API المالية وأرقام JSON/JSONL في مستودع البيانات بالهللات؛ تعرض الملفات البشرية الريال بمنزلتين عشريتين.
- `totalRevenue` القديم يعني الآن التحصيل المثبت من charge، و`refundTotal/refundedAmount` مجموع refund/partial_refund، والصافي الفرق بينهما. الصافي قد يكون سالبًا في فترة استرداد بلا تحصيل جديد.
- `bookedAmount/bookedCount` قيم الحجوزات الحالية المؤرخة بإنشاء الحجز، وتشمل حالات غير مدفوعة أو ملغاة. ليست فاتورة ضريبية معتمدة ولا مبيعات نقدية. بنود الخدمات النشطة تعرض قيمة البنود وكمياتها حسب تاريخ إنشائها؛ لا تضاف مرة ثانية إلى التحصيل.
- أعداد الحجوزات مميزة داخل المجموعة والفترة. جمع عدد الحجز عبر يوم تحصيله ويوم استرداده يكرره؛ لذلك تقرأ مجاميع التصدير المستقلة داخل اللقطة نفسها. `refundRate` نسبة الحجوزات ذات الاسترداد إلى الحجوزات ذات حركة مالية خلال الفترة، وليست نسبة استرداد مجموعة تذاكر مصدرة بعينها.
- `recognizedRevenue/deferredRevenue/ancillaryRevenue` في الملخص، وكذلك distance/RPK/yield/loadFactor، تصبح null. `getDeferredRevenue` يصرح بعدم التوفر. على المستهلك التعامل مع null؛ لا يحوله إلى صفر أو يحسب به مؤشرات ربحية.
- `generateReport/getReports` ينتجان معاينة شهرية حالية بحالة preview، لا سجل اعتماد أو قيد إقفال. تنزيل مستودع البيانات يحفظ لقطة قابلة للاستعادة والتحقق بالتجزئة وفق مالكه الموجود.
- تغيرت أسماء أعمدة التصدير المالي وورقة Excel إلى `Daily Settlements`. في مستودع البيانات تستخدم الحقول `postedCollectedAmountMinor/postedRefundedAmountMinor/netPostedAmountMinor` وتحتفظ الأرقام بنوع number. CSV يحمي النصوص من تفسيرها كصيغ، ويحافظ على الصافي السالب كرقم.
- كل صف مستودع بيانات يحمل الفترة و`snapshotSemantics=replace_period_snapshot`. يستبدل المستهلك لقطة الفترة المحددة؛ لا يضيف تشغيلين متداخلين كأنهما أحداث جديدة. الطلب التزايدي أو وجود lastExportTimestamp يرفض صراحة. الجدولة الحالية تنتج لقطات فترات؛ إنشاء تغذية أحداث بمؤشر ledger دائم مهمة منفصلة.

هذه تغييرات عقد فعلية؛ حُدثت مستهلكات المستودع المعروفة في الكود نفسه. يجب ترقية أي مستورد خارجي أو جدول تحليلي يفترض الأعمدة القديمة أو الأرقام غير القابلة لـnull قبل استيراد v2. الملفات القديمة المحفوظة لا يعاد تفسيرها تلقائيًا بالعقد الجديد.

## جودة الأدلة وحدود القراءة

يشمل المصدر قيود charge/refund/partial_refund بالريال المرتبطة بحجز موجود. لا يمثل دفتر البنك كله؛ شحن المحفظة غير المرتبط بحجز والعملات الأخرى وقيود الرسوم والتعديلات خارج التجميع. وجود القيد ليس إقرارًا بمطابقة كشف البنك.

يفحص `unmatchedCollectionEntries` التحصيل مقابل إيصال مزود مطابق في المرجع والحجز والدافع والعملة والمبلغ والنوع، مع قيد تحصيل واحد للمرجع. وللمحفظة يشترط حركة خصم مكتملة مطابقة وقيد تسوية واحد. القيد التاريخي غير المطابق يظل ظاهرًا في المبلغ المثبت مع علامة مراجعة؛ لا ينشئ التقرير إيصالًا مصطنعًا ولا يخفي المال المكرر. `reviewCollectionAmount` إجمالي التحصيل المرتبط بإيصالات review_required، وليس المبلغ الصافي القابل للاسترداد. `unpostedPaidBookings` يكشف حجزًا paid/refunded بلا قيد تحصيل SAR في تاريخه، ضمن فترة إنشاء الحجز المحددة.

تبقى مطابقة الاستردادات والسند الأصلي ومراجعة بيانات الإنتاج لدى أدوات التدقيق وأصحاب المجال؛ هذه المؤشرات ليست فحص سلامة شاملًا لكل قيود الدفتر. بيانات التصنيف وصفات الرحلة تُقرأ بحالتها الحالية؛ لا توجد هنا أبعاد تاريخية أو نسخة محاسبية مغلقة.

تقرأ كل استجابة مركبة داخل معاملة READ ONLY بعزل REPEATABLE READ. المقارنة الزمنية تستخدم epoch لضبط UTC حتى مع اختلاف المنطقة الزمنية للجلسة. تاريخ نهاية بصيغة يوم يشمل اليوم كاملًا، والحدود المفردة مدعومة؛ التاريخ المعطوب أو الفترة المعكوسة يرفضان قبل SQL. تتوقف القراءة عند مبلغ غير صالح أو خارج العدد الصحيح الآمن أو أكثر من 10000 مجموعة. حد ملف المستودع 8 MiB. لا يوجد بتر صامت، ولا يتحول خطأ SQL إلى صفر، ولا يسرب التشخيص نص SQL أو قيمه.

حد المجموعات يقيد المخرجات ولا يثبت زمن تنفيذ على دفتر إنتاج كبير. لا تدعي هذه المتابعة قياس أداء إنتاجي؛ يلزم قياس خطط الاستعلام والفهارس على حجم ممثل، خصوصًا القراءة الشاملة لكل الفترات.

## أدلة التحقق

نجح محليًا 78 اختبارًا موجهًا، تشمل إنشاء XLSX/PDF فعليين، وحالات الاسترداد الجزئي والصافي السالب والعدد المميز للحجوزات وحدود التواريخ والصلاحيات وأخطاء القراءة والواجهة العربية. نجحت المجموعة المحلية الكاملة: 1648 اختبارًا، وتُجاوز 241 اختبارًا يعتمد بعضها على خدمات غير متاحة محليًا. التجاوز لا يعد قبولًا.

يضيف `scripts/acceptance/financial-reporting.ts` أربعة فحوص إلى بوابة MySQL/Redis الحقيقية: مطابقة مجاميع الدفتر والتصديرات والمعاينات؛ تضارب القنوات وتعدد المقاطع؛ كشف التاريخ غير المطابق والتكرار والمراجعة واستبعاد العملة الأخرى ومطابقة المحفظة؛ وثبات القراءة أثناء تعديل متزامن ومنع UPDATE واستعادة لقطة مستودع البيانات مع بقاء الدفتر دون تغيير. تعدل هذه الفحوص بيانات صناعية وتعيدها قبل التدقيق والنسخ الاحتياطي. يصبح المتوقع 48 فحص قبول عند نجاح CI، إضافة إلى ستة فحوص نسخ واستعادة. نتائج التشغيل النهائية وروابطه تسجل في طلب الدمج؛ هذا التوثيق لا يفترض نجاح بوابة لم تنفذ بعد.

## القرار المحاسبي والمراحل المتبقية
