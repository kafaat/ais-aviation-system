# مطابقة أدلة BSP داخل AIS

تحدّد IATA في DISH أن RET تقرير المبيعات إلى BSP، وأن HOT ملف المحاسبة والمبيعات الوارد من BSP إلى الناقل. في مسار NDCLink ترسل الشركة ملف RET اليومي وتتلقى HOT، بينما تختلف مسؤولية الإرسال عند استخدام IFG. [تعريفات DISH لدى IATA](https://www.iata.org/en/publications/bspdish/) · [الإبلاغ عن مبيعات NDC](https://portal.iata.org/faq/articles/en_US/FAQ/How-should-I-report-NDC-sales-through-the-BSP/?l=en_US)

تعرض لوحة BSP للموظف المالي مسودة مبنية على القيود النقدية لحجوزات الوكلاء في يوم UTC مكتمل، بالريال والهللات. يدعم ملف المراجعة الداخلي `AIS-BSP-LOCAL-1` التحصيل والاسترداد الكلي والجزئي. تستبعد القراءة تمويل الحسابات الداخلية وتتوقف إذا وجدت تعديلاً أو رسماً يتطلب تصنيفاً، أو عملة أخرى، أو عدداً أكبر من 1000 حركة. التحويل المتوقع هو صافي المبيعات والاستردادات ليوم واحد. تستلزم التحويلات التي تجمع أياماً أو تخصم عمولات أو تخلط عملات ملف معالجة خاصاً بها.

1. اختر اليوم ثم أنشئ المسودة. يحفظ النظام نسخة وبصمة باسم المستأجر واليوم ومن أنشأها. تتطابق إعادة المحاولة، وتُرفض محاولة استبدال محتوى محفوظ تحت المرجع نفسه.
2. استورد بيانات HOT بعد أن يربط موظف المالية سطور البيان المستقل بحركات AIS. المثال اصطناعي، وتأتي المبالغ والهوية ونوع الحركة في الاستعمال من البيان الأصلي. يحتفظ النظام بمدخل المراجعة المحلي وبصمته.
3. استورد سطر كشف البنك المستقل، ثم أدخل مرجع التسوية وسطر البنك واطلب المطابقة. يعيد النظام قراءة الدفتر ويقارن الحركات واحدة بواحدة، ثم يطابق اتجاه التحويل ومبلغه. تَظهر المعرفات التي اختلفت حتى لو ألغت الفروق بعضها في الإجمالي.

```json
{
  "profile": "AIS-BSP-LOCAL-1",
  "direction": "inbound_hot",
  "tenantId": 12,
  "day": "2026-10-28",
  "currency": "SAR",
  "settlementReference": "SYNTH-SETTLE",
  "transferMinor": 500,
  "lines": [
    {
      "ledgerId": 1,
      "bookingId": 9,
      "agentId": 2,
      "kind": "sale",
      "amountMinor": 1500
    },
    {
      "ledgerId": 2,
      "bookingId": 9,
      "agentId": 2,
```

```json
}
```

يوضح الحقل `basis=local_evidence_only` نطاق النتيجة. تحتاج المطابقة التشغيلية إلى تحقق مستقل من المستند الأصلي، ومطابقة أرقام التذاكر الإلكترونية والضرائب، وملف DISH التعاقدي المعتمد، ومعرفات المزوّد وإقرارات الإرسال. لا تضم هذه الواجهة محوّل نقل أو إذناً بترحيل قيود بنكية أو تسوية مالية. تُختبر الخطوات محلياً في بوابة MySQL عبر `BSP-LOCAL-01`.
